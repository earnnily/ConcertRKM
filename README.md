# ระบบจองคอนเสิร์ตไหมไทย — ตลาดรักคุณ @rukkoon

**ติดตั้งบน Vercel + Supabase:** ดู [คู่มือติดตั้ง](DEPLOY_VERCEL.md)
และใช้ `.env.vercel.example` แทน Docker configuration ด้านล่าง
รองรับฐานข้อมูลใหม่ว่าง; ยังต้องตรวจการเชื่อมต่อคลาวด์และ LINE จริงก่อนเปิดขาย

งาน 20 พฤศจิกายน 2569 ประตูเปิด 17.00 น. ภาษาไทยทั้งบอทและหลังบ้าน

## สถานะของชุดนี้

ระบบพร้อมติดตั้งและทดสอบ ไม่ได้เชื่อม LINE OA หรือเปิดขายจริงให้แล้ว หน้าเว็บที่เผยแพร่ผ่าน Sites เป็นหน้าทดลองส่วนตัว ข้อมูลทดลองอยู่ในหน่วยความจำและหายเมื่อรีเฟรช ไม่ใช่ Webhook หรือฐานข้อมูลจริง

ระบบจริงใน `app/` ใช้ Python 3.11+ และ SQLite ไม่ต้องติดตั้ง Python package เพิ่ม ระบบต้องรันบนเซิร์ฟเวอร์ HTTPS ที่ LINE เข้าถึงได้ และมีพื้นที่ถาวรสำหรับฐานข้อมูลและสลิป

## กติกาที่ตั้งไว้

| โซน | โควตา | ราคา | เสริม |
| --- | --- | --- | --- |
| VIP | 42 โต๊ะ | 2,000 บาท/โต๊ะ 4 คน | ไม่เกิน 2 คน/โต๊ะ คนละ 200 บาท |
| พิเศษ | 14 โต๊ะ | 1,600 บาท/โต๊ะ 4 คน | ไม่เกิน 1 คน/โต๊ะ คนละ 200 บาท |
| ลานนั่ง | 1,000 ใบ | 180 บาท/ใบ | ไม่มี |

- VIP และพิเศษลูกค้าเลือกเลขโต๊ะ: A1–F7 จำนวน 42 โต๊ะ และ G1–H7 จำนวน 14 โต๊ะ ส่วน A4 เริ่มต้นว่างตามคำสั่งเจ้าของงาน ไม่ได้นำยอดจองเดิมจากภายนอกมาใส่
- ลานนั่งเลือกโต๊ะหน้างาน มาก่อนได้เลือกก่อน ขายรายบัตร 180 บาท หรือรายโต๊ะ 720 บาท (4 บัตร) หักจากโควตาร่วม 1,000 บัตร
- ตัวอย่าง: VIP 2 โต๊ะ เสริม 3 คน = 4,600 บาท
- รายการละ 1–10 โต๊ะหรือใบ มีรายการรอชำระ/รอตรวจได้ครั้งละหนึ่งรายการต่อ LINE user
- กันโควตา 15 นาทีหลังยืนยัน เมื่อหมดเวลาและยังไม่ส่งสลิป คืนโควตาอัตโนมัติ ตัวทำงานเบื้องหลังตรวจทุก 0.5 วินาที และตรวจซ้ำก่อนจอง/อัปโหลด/อนุมัติ
- สลิปที่รับเข้าระบบทันเวลาและตรวจรูปสำเร็จ เปลี่ยนสถานะเป็นรอตรวจ พร้อมคงโควตาไว้ แม้เลย 15 นาที
- รับ JPG/PNG ขนาดไม่เกิน 10 MB ไม่ตรวจธนาคารอัตโนมัติ แอดมินต้องเทียบยอดเข้าบัญชีจริง
- แอดมินอนุมัติ ส่งรหัสจองผ่าน LINE; ไม่อนุมัติต้องระบุเหตุผลและคืนโควตา ลูกค้าที่โอนแล้วต้องติดต่อแอดมินก่อนโอนซ้ำ
- หลังบ้านเช็กอินได้หนึ่งครั้งต่อรายการจอง ยังไม่มี QR scanner
- หน้าผังโต๊ะมีสองมุมมองสำหรับลานนั่ง 1,000 บัตร / 250 โต๊ะ พร้อมยอดคงเหลือเป็นโต๊ะเต็มและบัตรเศษ เลขโต๊ะลานนั่งเป็นผังอ้างอิง ไม่ผูกกับผู้ซื้อ
- ผังลานนั่งที่เสนอ: A–H คอลัมน์ 0 และ 8–11 รวม 40 โต๊ะ; I–Y คอลัมน์ 0–11 รวม 204 โต๊ะ; Z0–Z5 อีก 6 โต๊ะ รวม 250 โต๊ะ
- ปุ่มบันทึกขายลานนั่งในหลังบ้านใช้สำหรับยอดที่ตรวจรับเงินแล้ว นับเป็นยืนยันแล้วทันที เลือกหน่วยบัตรหรือโต๊ะได้ ไม่มีการส่ง LINE เพราะเป็นรายการบันทึกผ่านแอดมิน
- หน้างาน 200 บาทไม่ได้รวมระบบขายหน้างานในชุดนี้ ต้องบริหารไม่ให้บัตรหน้างานทับกับโควตาที่จองแล้ว

## ติดตั้งด้วย Docker Compose (แนะนำ)

1. จัดเตรียมเซิร์ฟเวอร์ที่ติดตั้ง Docker และ Docker Compose และโดเมนที่ชี้ DNS ไปยังเซิร์ฟเวอร์ เปิดพอร์ต 80/443
2. แตก ZIP แล้วคัดลอก `.env.example` เป็น `.env` ตั้งสิทธิ์ไฟล์ให้อ่านเฉพาะผู้ดูแล
3. กรอกใน `.env`:
   - `BOOKING_DOMAIN` เช่น booking.example.com (ไม่ใส่ https://)
   - `ADMIN_PASSWORD` รหัสสุ่มอย่างน้อย 16 ตัวอักษร
   - `LINE_CHANNEL_SECRET` จาก Messaging API channel ที่ผูกกับ @rukkoon
   - `LINE_CHANNEL_ACCESS_TOKEN` จาก channel เดียวกัน
   - คง `ALLOW_INSECURE_LOCALHOST=0` สำหรับการใช้งานจริง
4. รัน `docker compose up -d --build` Caddy จะออกใบรับรอง HTTPS และส่งต่อไปยังแอป ฐานข้อมูลและสลิปอยู่ใน volume `booking-data`
5. เปิด `https://โดเมนของคุณ` ไปที่ “เชื่อมต่อ LINE” เข้าสู่ระบบด้วยรหัสแอดมิน
6. กรอกธนาคาร เลขบัญชี ชื่อบัญชี ในหน้า “ตั้งค่าการจอง” ยังไม่ต้องเปิดรับจอง

ห้ามใช้ `docker compose down -v` กับข้อมูลจริง เพราะจะลบ volume ฐานข้อมูลและสลิป ใช้แอปหนึ่ง instance ต่อฐานข้อมูล SQLite นี้

## เชื่อม LINE @rukkoon

1. ใน LINE Official Account Manager ตรวจว่าบัญชี @rukkoon เปิดใช้ Messaging API และผูกกับ channel ที่ถูกต้อง
2. ใน LINE Developers ของ Messaging API channel ตั้ง Webhook URL เป็น `https://โดเมนของคุณ/webhook/line`
3. กด Verify แล้วเปิด Use webhook แนะนำเปิด Webhook redelivery ด้วย ระบบตรวจลายเซ็น X-Line-Signature และกัน webhookEventId ซ้ำ
4. ตั้งค่า auto-reply/greeting ของ OA ให้สอดคล้องกับบอท เพื่อไม่ให้ตอบซ้ำ
5. เมนู Rich Menu (ถ้ามี) ให้ส่งข้อความ `จองบัตร`, `ดูการจอง`, `ติดต่อแอดมิน` ได้เลย ชุดนี้ไม่แก้ Rich Menu ใน OA อัตโนมัติ
6. เพิ่มเพื่อน OA และส่ง `จองบัตร` บอทจะตอบด้วย Quick Reply ให้กดเลือก
7. หลังตั้งค่าธนาคารครบและ LINE พร้อม เปิดรับจองผ่านหลังบ้าน ทดสอบหนึ่งรายการให้จบทั้งส่งสลิป ตรวจยอดจริง และอนุมัติ จากนั้นจัดการรายการทดสอบก่อนประชาสัมพันธ์ (แนะนำใช้ environment/ฐานข้อมูลทดสอบแยก)

อย่าส่ง Channel Secret, access token หรือรหัสผ่านแอดมินผ่านแชต/อีเมลสาธารณะ อย่าใส่ใน HTML หรือ Git

## ทดลองรันในเครื่อง

ใช้ Python 3.11+ ตั้ง environment variables ตาม `.env.example` ก่อนเริ่ม (โปรแกรมไม่อ่าน .env เอง; Docker Compose อ่านให้)

```bash
export ADMIN_PASSWORD='replace-with-a-long-random-password'
export ALLOW_INSECURE_LOCALHOST=1
python3 app/server.py
```

เปิด http://127.0.0.1:8080 ค่าเริ่มต้น bind เฉพาะ localhost เท่านั้น อย่าเปิด `ALLOW_INSECURE_LOCALHOST=1` บนเซิร์ฟเวอร์จริง หน้าทดลองแบบ static อยู่ที่ `dist/index.html` และไม่เชื่อมฐานข้อมูล

## การใช้งานหลังบ้าน

- หน้าภาพรวม: จำนวนคงเหลือ ยอดที่อนุมัติ และรายการล่าสุด
- รายการจอง: ค้นหารหัส ชื่อ เบอร์โทร กรองสถานะ ดูสลิป อนุมัติ/ไม่อนุมัติ เช็กอิน และส่งออก CSV
- ตั้งค่าการจอง: ข้อมูลบัญชีและเปิด/ปิดรับจอง การปิดรับจองไม่ยกเลิกรายการเดิม
- เชื่อมต่อ LINE: ขั้นตอนติดตั้งและเข้าสู่ระบบแอดมิน
- Session แอดมินมีอายุ 8 ชั่วโมง ใช้ HttpOnly / Secure / SameSite=Strict cookie
- สำรองฐานข้อมูลด้วย SQLite backup API พร้อมสำรองโฟลเดอร์สลิป เก็บไฟล์สำรองในพื้นที่ที่จำกัดสิทธิ์ การคัดลอกเฉพาะ .sqlite3 ขณะรันอาจไม่รวม WAL

## สถานะผิดปกติ

การรับ webhook จะบันทึกก่อนตอบ 200 และประมวลผลใน background บอทใช้ Reply API ตอบการจอง และ Push API แจ้งผลอนุมัติ Push ที่ล้มเหลวจะลองใหม่สูงสุด 10 ครั้งแบบหน่วงเวลา หากใช้เกินโควตาข้อความ LINE หรือผู้ใช้บล็อก OA การแจ้งอาจไม่สำเร็จ ลูกค้ายังพิมพ์ “ดูการจอง” ได้

หน้าแอดมินแสดงจำนวน event ที่ประมวลผลล้มเหลวและข้อความค้างส่ง ตรวจ server log และฐานข้อมูลเพื่อแก้ไข (อย่าแสดงข้อมูลส่วนตัวหรือ token ใน log) event ที่ล้มเหลวจะไม่ถูกส่งซ้ำเอง เพราะต้องตรวจสอบผลกระทบก่อน ไม่มีหน้าจอซ่อม event อัตโนมัติในรุ่นนี้

## การทดสอบ

```bash
python3 -m unittest discover -s tests -v
```

ผ่าน 11 กลุ่ม: คำนวณราคา/จำกัดที่นั่งเสริม, จองพร้อมกัน 70 คำขอไม่เกิน 42 โต๊ะ, หมดเวลา, คงโควตารอตรวจ, ป้องกันอนุมัติ/เช็กอินซ้ำ, คืนโควตาเมื่อไม่อนุมัติ, ปิดรับจองและ idempotency, ลายเซ็น webhook, บทสนทนาจอง, HTTP login/logout และ webhook ซ้ำ (บางกลุ่มรวมหลายกรณี)

ข้อจำกัดการตรวจในรอบสร้าง: ยังไม่ทดสอบกับ LINE OA จริง, บัญชีธนาคารจริง, TLS/Docker บนเซิร์ฟเวอร์ปลายทาง หรือ browser interaction เนื่องจากไม่มี runtime browser QA ที่ Sites ต้องใช้ ต้องทดสอบจริงก่อนเปิดรับเงิน

## ฐานข้อมูลเลขโต๊ะ (รุ่นปรับปรุง)

เพิ่มตาราง booking_tables เชื่อม booking_id กับ table_id ตรวจโต๊ะซ้ำใน transaction เดียวกับการหักโควตา สถานะ pending/review/confirmed กันโต๊ะ ส่วน expired/rejected/cancelled คืนโต๊ะ การเริ่มโปรแกรมจะเพิ่มตารางใหม่โดยไม่ลบฐานข้อมูลเดิม หากมีรายการเก่าจากรุ่นไม่มีเลขโต๊ะ ต้องให้ผู้ดูแลจัดสรรเลขโต๊ะและตรวจยอดก่อนเปิดขายรุ่นนี้ ห้ามอนุมานเลขโต๊ะจากจำนวนรายการ

ทดสอบตรรกะหน้าเว็บเพิ่มเติมด้วย `node tests/test_ui.mjs` ตรวจ 42 VIP / 14 พิเศษ / 250 โต๊ะลาน / 1,000 ตัวแสดงบัตร รวมถึงขาย 3 โต๊ะหัก 12 บัตร และเลือก A4 ได้ ยังไม่ได้ตรวจการแสดงผลด้วยเบราว์เซอร์จริง
